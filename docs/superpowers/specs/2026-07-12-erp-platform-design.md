# Octopus ERP 基础平台设计

## 目标

为 `/Users/lobster/Test/test-cc-umc` 中的 UMC、OA、PLM、CRM、WMS、MES、FIN、HRM、OMS 提供可复用基础层，同时支持三种部署形态：统一 ERP 应用框架、模块化单体、独立微服务。

## 约束

- v1.6–v1.9 保持现有 `OctopusEx.WebCore` API 兼容。
- 新能力优先使用独立扩展包和适配层，不强制现有 ERP 一次性重写。
- v2.0 才移除已废弃 API。
- 业务规则留在 ERP 模块，OctopusUtils 只提供上下文、基础设施、可靠性和开发规范。

## 分层设计

1. **ERP 应用框架层**：用户、租户、组织、权限、数据范围、响应、审计和应用服务基座。
2. **模块化运行时层**：模块契约、依赖图、生命周期、模块配置、Endpoint、迁移和权限资源。
3. **微服务基础设施层**：HTTP/Webhook、服务发现、Outbox/Inbox、幂等、重试、补偿和 Telemetry。
4. **开发平台层**：dotnet 模板、通用业务组件、契约测试、架构测试和发布门禁。

## 关键边界

- UMC 负责身份、组织和权限数据；业务系统只缓存必要的用户投影。
- 跨模块调用优先使用公共契约和领域/集成事件，禁止直接引用其他模块的 EF 实体。
- 模块化单体和微服务使用相同的应用服务与事件契约，差异只存在于宿主和传输层。
- 可靠投递使用 Outbox/Inbox；不在 v1.x 引入跨库分布式事务。

## Phase 交付顺序

- **v1.6**：统一上下文、权限策略、应用服务和 UMC/CRM 迁移样板。
- **v1.7**：模块契约、模块宿主、WebCore 拆包和 CRM/OA/PLM 模块化样板。
- **v1.8**：服务调用、HMAC Webhook、Outbox/Inbox、Saga 基础和 Aspire 接线。
- **v1.9**：项目模板、通用业务组件、契约/架构测试和 ERP 全链路 Sample。
- **v2.0**：API 冻结、废弃 API 清理、九个 ERP 系统迁移和生产门禁。

## 首批验证系统

- UMC：验证认证、组织、角色、数据权限和当前用户上下文。
- CRM：验证 CRUD、审批、Webhook、幂等和跨服务事件。
- OA：验证模块化审批引擎与跨系统通知。

## 成功标准

- 新 ERP 服务可以通过统一入口接入认证、权限、审计、健康检查和 Telemetry。
- 同一模块可在模块化单体和独立微服务宿主中运行。
- 跨服务消息至少一次投递时不会造成重复业务结果。
- 现有 WebCore 使用者在 v1.x 无需修改即可继续编译和运行。
- v2.0 提供明确迁移文档、兼容矩阵和回滚策略。
